# จุดสังเกตใช้ NFKC แม้ "น้ำ" จะถูกนับเป็น 4 ตัวอักษร

จุดสังเกตถูก normalize ด้วย NFKC ก่อนตรวจความยาว ปิดเบอร์โทร และรวมรายงานซ้ำ (RPT-REQ-004) NFKC แปลงตัวอักษรที่หน้าตาต่างแต่ความหมายเดียวกันให้เป็นแบบเดียว เช่น เลขเต็มความกว้าง `０８１` เป็น `081` ทำให้การปิดเบอร์โทรจับเบอร์ที่พิมพ์เลี่ยงได้ ผลข้างเคียงคือ "ำ" (U+0E33) ถูกแยกเป็น "ํ" + "า" ข้อความที่เก็บจึงไม่ตรงกับที่พิมพ์ทีละ byte และ "น้ำ" นับเป็น 4 ตัวอักษรแทน 3 เราเลือกความปลอดภัยของการปิดเบอร์โทรมากกว่าการเก็บ byte ให้ตรง เพราะบนจอแทบไม่ต่างกัน

## Considered Options

- **NFC แล้วแปลงเลขเต็มความกว้างและช่องว่างแปลกๆ เอง:** เก็บ "ำ" ได้ตรง แต่ต้องไล่เก็บกรณีที่ NFKC ทำให้อยู่แล้วเอง พลาดกรณีเดียวเบอร์ก็หลุด จึงไม่เลือก
