# ฟีเจอร์: คนในพื้นที่รายงานจุดน้ำท่วม

## Problem — ปัญหาที่ผู้ใช้เจอ

ตอนนี้แอปแสดงเฉพาะระดับน้ำล่าสุดจากสถานีวัดในแต่ละเขต (`GET /districts/:id`) แต่สถานีวัดมีน้อย และบอกไม่ได้ว่าถนนหรือซอยที่คนกำลังจะผ่านน้ำท่วมจริงหรือไม่ เขตที่ไม่มีสถานีวัด เช่น สายไหม ไม่มีข้อมูลเลย

ผู้อ่านหลักคือคนในเขตเดียวกัน หรือคนที่กำลังจะเดินทางผ่านเขตนั้น เขาต้องการตัดสินใจว่า "ถนนหรือจุดนี้ ภายในไม่กี่ชั่วโมงข้างหน้า ผ่านได้ไหม หรือควรเลี่ยง" ข้อมูลที่ตอบคำถามนี้ได้ดีที่สุดมาจากคนที่อยู่ตรงนั้นและเห็นน้ำด้วยตาตัวเอง

เจ้าหน้าที่เขตและหน่วยกู้ภัยไม่ใช่กลุ่มเป้าหมายในรอบนี้ เพราะเขาต้องการข้อมูลที่ยืนยันแล้ว ซึ่งทำให้ขอบเขตงานใหญ่ขึ้นมาก

## Proposed outcome — ทำเสร็จแล้วอะไรเปลี่ยน และวัดผลยังไง

### สิ่งที่เปลี่ยน

- ผู้ใช้ส่งรายงานได้โดยไม่ต้องล็อกอิน ประกอบด้วย
  - **เขต** เลือกจาก 12 เขตใน `src/districts.ts`
  - **จุดสังเกต** ข้อความสั้นๆ เช่น "หน้าปากซอยลาดพร้าว 71" จำกัดความยาว ไม่เก็บพิกัด GPS
  - **ความลึก** เลือกระดับเทียบร่างกาย เช่น ตาตุ่ม เข่า เอว แล้วระบบแปลงเป็น cm จำนวนเต็มตามตารางคงที่ตอนบันทึก
  - **เวลาที่เห็น** ย้อนหลังได้ไม่เกิน 3 ชั่วโมง ห้ามเป็นเวลาในอนาคต เก็บเป็น UTC แสดงเป็นเวลากรุงเทพฯ (UTC+7)
- รายงานแสดงทันทีโดยไม่ต้องรอคนตรวจ พร้อมป้าย "ผู้ใช้รายงาน ยังไม่ยืนยัน" และแสดงแยกจากค่าของสถานีวัด
- รายงานแสดงอายุเสมอ เช่น "เห็นเมื่อ 40 นาทีก่อน" และหยุดแสดงบนหน้าหลักหลังผ่านไป 6 ชั่วโมงนับจากเวลาที่เห็น
- ผู้รายงานไม่ระบุตัวตน ระบบไม่เก็บเบอร์โทร ไม่เก็บ IP ลงในรายงานหรือ log

### วัดผลยังไง

repo นี้เป็นตัวอย่างสอนและไม่มีผู้ใช้จริง ตัวชี้วัดด้านล่างจึงใช้เป็นเกณฑ์ตรวจงานด้วย test ไม่ใช่ตัวเลขจากการใช้งานจริง ตัวเลขทั้งหมดเป็นค่าเริ่มต้นที่ยังรอให้ Save ยืนยัน (ดู Open questions)

| ด้าน | ตัวชี้วัด |
| ---- | --------- |
| ใช้งานได้ | ส่งรายงานสำเร็จภายใน 30 วินาทีหลังเปิดฟอร์ม และอัตราส่งไม่ผ่านเพราะข้อมูลไม่ถูกต้องต่ำกว่า 10% |
| มีข้อมูลให้อ่าน | ในช่วงฝนตกหนัก เขตที่มีสถานีวัดอย่างน้อย 1 สถานี ได้รับรายงานที่ยังไม่หมดอายุอย่างน้อย 1 รายการ |
| ความสด | ค่ามัธยฐานของอายุรายงานที่แสดงอยู่ไม่เกิน 2 ชั่วโมง |
| ความปลอดภัย | ไม่มีเบอร์โทรหรือ IP หลุดใน log (ตรวจด้วย test) และรายงานสแปมหลุดถึงหน้าแสดงผลน้อยกว่า 5% ของที่ส่งเข้ามา |

## Constraints — เรื่องความปลอดภัย งบ กฎบริษัท และสิ่งที่ห้ามแตะ

### กติกาที่ repo กำหนดไว้แล้ว

- ความลึกและระดับน้ำเป็นจำนวนเต็มหน่วยเซนติเมตร เวลาเก็บเป็น UTC และแสดงเป็น UTC+7 (`README.md`, `src/time.ts`)
- เขตมี 12 slug ตายตัว (`src/districts.ts`) รายงานต้องอ้างเขตจากรายการนี้เท่านั้น
- ทุก response ต้องแนบ `NOTICE` ว่าเป็นตัวอย่างเพื่อการเรียน ไม่ใช่ประกาศเตือนภัยทางการ (`src/app.ts`)
- การ routing อยู่ใน `handle()` ที่แยกจาก `node:http` เพื่อให้ test ง่าย ฟีเจอร์ใหม่ต้องรักษาโครงนี้ไว้

### ความปลอดภัยและข้อมูลส่วนบุคคล (PDPA)

- ไม่เก็บเบอร์โทร ชื่อ บัญชีผู้ใช้ หรือพิกัด GPS ของผู้รายงาน
- ไม่เก็บ IP ลงในรายงานหรือ log การจำกัดจำนวนการส่งต่อ IP/อุปกรณ์ทำได้ แต่ห้ามบันทึกค่านั้นถาวร
- ผู้ใช้อาจพิมพ์เบอร์โทรหรือข้อมูลส่วนตัวลงในช่องจุดสังเกตเอง ต้องจำกัดความยาวและห้ามข้อมูลนี้หลุดลง log
- ต้องมีมาตรการกันรายงานรัวและรายงานมั่ว (จำกัดจำนวน รวมรายงานซ้ำ) รายละเอียดตัดสินใจในขั้น spec และ plan

### งบและขอบเขต

- งบ 0 บาท รันในเครื่อง (`npm run dev`) ไม่ deploy ขึ้นระบบจริง ไม่เปิดให้ประชาชนใช้
- เก็บรายงานใน memory หรือไฟล์ในเครื่อง ไม่มี DB ภายนอก
- ไม่เพิ่ม runtime dependency ถ้าจะลง package ใหม่ต้องถาม Save ก่อน

### สิ่งที่ห้ามแตะ

- **ห้าม POST หรือ DELETE ไปที่ `flood-api.rooptanjai.com`** (แผนที่ ROOP TAN JAI Flood Watch) อ่านด้วย GET ได้เท่านั้น เพราะคนใช้แผนที่นั้นตัดสินใจจริงในช่วงน้ำท่วม
- ห้ามแก้ไฟล์ test เพื่อให้ test ผ่าน
- ห้าม commit ตรงเข้า `main` ให้ทำบน branch `feat/` หรือ `fix/` และ Save เป็นคน push, เปิด PR และ merge เอง
- ห้ามนำข้อมูลสมมติใน `data/stations.json` ไปอ้างเป็นข้อมูลจริง
