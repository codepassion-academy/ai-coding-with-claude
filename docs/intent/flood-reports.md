# ฟีเจอร์: ให้คนในพื้นที่รายงานจุดน้ำท่วม

## Problem

แอปน้ำท่วมไหมแสดงเฉพาะระดับน้ำจากสถานีวัด ซึ่งมีไม่ครบทุกเขต (เช่น สายไหมไม่มีสถานี) และสถานีวัดเป็นจุดเดียวต่อคลอง ไม่ได้บอกว่าถนนหรือซอยตรงไหนน้ำท่วมจริง

คนที่อยู่ในพื้นที่เห็นสถานการณ์ก่อนและละเอียดกว่า แต่ตอนนี้ไม่มีช่องทางให้บอกใคร ผู้ใช้ที่ต้องตัดสินใจว่าจะเดินทางผ่านจุดไหน จึงไม่มีข้อมูลระดับจุดสังเกต

## Proposed outcome

ทำเสร็จแล้วสิ่งที่เปลี่ยน

- คนทั่วไปรายงานจุดน้ำท่วมได้ผ่าน**API และหน้าเว็บฟอร์ม** โดยกรอก เขต (เลือกจาก 12 เขตที่มีในระบบ) จุดสังเกต (ข้อความอิสระ) ความลึก (จำนวนเต็มเซนติเมตร) และเวลาที่เห็น
- รายงานแสดงสาธารณะทันที แต่**แยกส่วนจากค่าสถานี** และติดป้าย "รายงานจากประชาชน ยังไม่ยืนยัน" ไม่ปนกับข้อมูลที่ตรวจวัด
- รายงานแต่ละรายการแสดง "เมื่อ X นาทีที่แล้ว" และหายจากหน้าแสดงเมื่อครบ 6 ชั่วโมงนับจากเวลาที่เห็น (เก็บไว้ดูย้อนหลัง ไม่ลบ)
- รายงานเขตเดียวกัน จุดสังเกตเดียวกัน ภายใน 30 นาที รวมเป็นรายการเดียว นับจำนวนผู้รายงาน และแสดงความลึกล่าสุด การจับคู่จุดสังเกตใช้ข้อความที่ปรับรูปแล้ว (ตัดช่องว่าง ตัวพิมพ์ คำนำหน้า) จึงรวมได้ไม่ครบทุกกรณี และยอมรับข้อนี้
- ผู้ดูแลระบบซ่อนรายงานได้ (ซ่อน ไม่ลบ เก็บไว้ตรวจสอบ)

**กติกาการรับรายงาน**

| เรื่อง | ค่าที่ตกลง |
| ------ | ---------- |
| เวลาที่เห็น | ย้อนหลังได้ไม่เกิน 6 ชั่วโมง ห้ามเป็นเวลาอนาคต |
| ความลึก | จำนวนเต็ม 1 ถึง 300 ซม. (ค่านอกช่วงปฏิเสธ) |
| จำนวนต่อผู้ส่ง | ไม่เกิน 5 รายงานต่อชั่วโมง เกินตอบ 429 |
| ช่องจุดสังเกต | จำกัดความยาว และปิดเบอร์โทรที่หลุดเข้ามาในข้อความ |

**วัดผลอย่างไร**

- ตัวชี้วัดหลัก: สัดส่วนของ 12 เขตที่มีรายงานอย่างน้อย 1 รายการในช่วงน้ำท่วม โดยดูเขตที่ไม่มีสถานีวัดเป็นพิเศษ เพราะเป็นช่องว่างที่ฟีเจอร์นี้ควรเติม
- ตัวเตือน: สัดส่วนรายงานที่ถูกซ่อนหรือถูกปฏิเสธเทียบกับรายงานทั้งหมด ถ้าสูงผิดปกติแสดงว่าการกันสแปมมีปัญหา
- ดูประกอบ ไม่ตั้งเป็นเป้า: จำนวนรายงานต่อวัน (ขึ้นกับสถานการณ์น้ำจริง) และเวลาตั้งแต่เปิดหน้าจนส่งสำเร็จ
- ยังไม่ตั้งตัวเลขเป้าหมาย เพราะยังไม่มีข้อมูลผู้ใช้จริง (ดู Open questions)

## Constraints

**ความปลอดภัยและข้อมูลส่วนบุคคล**

- ผู้รายงานไม่ต้องล็อกอิน ระบบเก็บเฉพาะแฮชของ IP หรืออุปกรณ์ไว้จำกัดจำนวนและตรวจสแปม ไม่แสดงต่อสาธารณะ ไม่ขอเบอร์โทรหรือชื่อ
- ช่องจุดสังเกตต้องกรองเบอร์โทรที่หลุดเข้ามา ห้ามบันทึกลง log
- เจ้าของรายงานลบเองไม่ได้ในรอบแรก เพราะเราไม่ระบุตัวตนผู้รายงาน
- ช่องทางซ่อนรายงานของผู้ดูแลระบบต้องป้องกันด้วยรหัสลับ ห้ามฝังรหัสไว้ในโค้ดหรือ repo

**เรื่องที่ห้ามแตะ**

- ห้ามส่งรายงานทดสอบไปที่ระบบจริง (`flood-api.rooptanjai.com`) อ่านข้อมูลด้วย GET ได้อย่างเดียว ห้ามส่งหรือลบ (ตามที่ README ระบุ)
- ไม่เปลี่ยนความหมายของข้อมูลสถานีเดิม ค่าจากสถานีกับรายงานประชาชนต้องแยกกันเสมอ
- ไม่แก้ผลของ route เดิมในแบบที่ทำให้ test ปัจจุบันพัง การเพิ่มรายงานเป็นการเพิ่มส่วนใหม่ในผลลัพธ์
- ข้อมูลใน repo เป็นข้อมูลสมมติเพื่อการเรียน ต้องคงข้อความ `NOTICE` และห้ามนำไปใช้ตัดสินใจเรื่องความปลอดภัยจริง

**กติกาที่ใช้ทั้ง repo**

- ความลึกเป็นจำนวนเต็มเซนติเมตร
- เวลาเก็บเป็น UTC และแสดงเป็นเวลากรุงเทพฯ (+07:00)
- เขตเลือกจากรายการ 12 เขตใน `src/districts.ts` (ใช้ id แบบ slug เช่น `lat-phrao`) ไม่ให้พิมพ์ชื่อเขตเอง

**งบและการโฮสต์**

- เก็บรายงานลงไฟล์บนเครื่องเดียว ไม่ใช้ฐานข้อมูลในรอบแรก โดยแยกส่วนเก็บข้อมูลไว้หลังอินเทอร์เฟซเดียว เพื่อเปลี่ยนเป็นฐานข้อมูลภายหลังได้ ข้อจำกัดคือรองรับเซิร์ฟเวอร์เครื่องเดียวเท่านั้น
- ยังไม่ทราบงบและที่โฮสต์จริง (ดู Open questions)
